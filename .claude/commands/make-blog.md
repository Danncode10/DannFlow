# /make-blog

Generate one or more publish-ready blog posts for the current DannFlow project. The command reads the project context, creates distinct SEO-focused drafts, and can publish them through `scripts/publish-blog-post.mjs` when the blog feature and Supabase environment are configured.

User topic or angle: **$ARGUMENTS**

## Context to read first

1. `business.json` for business name, industry, audience, website, SEO keywords, and whether `features.blog` is enabled.
2. `README.md` and `PROJECT_CONTEXT.md` when present, to understand the project voice and product boundaries.
3. Visible recent blog titles/excerpts/screenshots in the conversation, to avoid near-duplicate topics and cover image ideas.

If `business.json.features.blog` is false, stop and say the blog feature is disabled for this project.

## Argument parsing

1. Parse `blog_count` from `$ARGUMENTS` when present. Accept `blog_count = 5`, `blog_count=5`, `count = 5`, or `count=5`.
2. Default `blog_count` to `1`.
3. Clamp below `1` to `1`.
4. If above `5`, stop and tell the user the maximum is `5`; do not publish anything.
5. Remove the `blog_count` / `count` token from the topic angle before interpreting the topic.
6. If `--draft-only` is present, do not publish. Return the field package only.

## Content strategy

For each post, choose a distinct combination of:

- content lane: product education, how-to workflow, buyer checklist, operations guide, comparison, mistake list, customer scenario, FAQ deep dive, implementation plan, industry trend, local/service-area guide
- article format: checklist, step-by-step workflow, before-and-after scenario, role-specific guide, decision tree, audit worksheet, template walkthrough, myth vs reality, red flags and fixes, starter system
- reader intent: learn, compare, troubleshoot, choose, set up, improve, prepare, audit
- concrete scenario: a real moment where the reader would need the product or service
- cover image concept: a photographic Pexels search phrase with a clear visual subject and action

When the user gives a topic, honor it, but still make the title, structure, first paragraph, examples, and image concept distinct from visible recent posts.

## SEO requirements

Every post must include:

- `title`: clear, specific, and useful
- `slug`: kebab-case URL slug
- `excerpt`: 2-3 sentence blog-card summary
- `seo_title`: search title, ideally under 60 characters
- `seo_description`: search description, ideally 150-160 characters
- `primary_keyword`: one focused long-tail keyword family
- `search_intent`: one sentence naming the exact reader problem/query
- `internal_links`: 1-3 newline-separated known paths to include or consider, such as `/blog`, `/#features`, `/pricing`, or related blog paths if known
- `content_markdown`: full post body without the title or metadata
- `image_alt_text`: one descriptive sentence tied to the post
- `image_caption`: one short caption
- `pexels_credit_url`: blank unless the exact Pexels photo URL is known
- `pexels_keyword`: one concise Pexels search phrase
- `pexels_description`: plain-English image selection guidance
- `facebook_caption`: short launch caption for a Facebook Page
- `reddit_discussion_prompt`: discussion-first prompt that does not sound like an ad
- `seo_quality_score`: estimated 0-100 score; target 85+
- `pre_publish_warnings`: newline-separated warnings, or an empty string if ready

Use the project domain and audience from `business.json`. Do not hardcode another brand, vertical, city, country, or product category unless the current project context says so.

## Writing rules

- Start with a concrete moment, problem, or scenario. Avoid generic openings.
- Keep the content educational and operational. Do not make unverifiable claims or guarantee outcomes.
- Include at least one practical example, checklist, mini-template, or handoff script.
- Use one focused keyword family naturally in the title, SEO title, meta description, headings, and body. Do not keyword stuff.
- Vary article structure across multiple posts.
- Do not use generic title formulas such as "ultimate guide", "everything you need to know", "boost productivity", "transform your business", or "revolutionize your workflow".
- Do not mention that the post was generated by AI.
- Do not include citations unless the user explicitly requests sourced content.
- Keep the content field clean for direct paste into the editor: no frontmatter, no duplicate title, no metadata block.

## Cover image rules

Choose a Pexels keyword that is visually specific and different from recent visible covers. Build the keyword from one visual subject plus one setting or action.

Good patterns:

- `team reviewing documents table`
- `calendar appointment close up`
- `person writing checklist notebook`
- `small business owner laptop`
- `customer consultation table`
- `filing cabinet office folders`
- `email inbox laptop workspace`
- `receipt calculator desk`
- `planner sticky notes desk`
- `hands sorting paper files`

Do not invent a Pexels credit URL. Leave `pexels_credit_url` blank until an exact image is selected.

## Auto-publish workflow

When `--draft-only` is not present:

1. Compose the requested number of blog payloads privately.
2. Do not create or upload cover images. Leave `cover_image_url` empty.
3. Write the payload to a temporary JSON file outside the repo, such as `/tmp/dannflow-blog-posts.json`.
4. Use this object shape:

```json
[
  {
    "title": "SEO-friendly post title",
    "slug": "kebab-case-url-slug",
    "excerpt": "Blog card excerpt.",
    "seo_title": "SEO title under 60 characters",
    "seo_description": "150-160 character meta description.",
    "primary_keyword": "focused long-tail keyword phrase",
    "search_intent": "The practical search question this article answers.",
    "internal_links": "/blog\n/#features",
    "image_alt_text": "Descriptive cover image alt text tied to the article topic.",
    "image_caption": "Short caption explaining why the image fits the article.",
    "pexels_credit_url": "",
    "facebook_caption": "Short Facebook Page caption for this post.",
    "reddit_discussion_prompt": "Discussion-first Reddit prompt related to the post topic.",
    "seo_quality_score": 90,
    "pre_publish_warnings": "",
    "content_markdown": "Full article body in markdown, without the title or metadata.",
    "pexels_keyword": "one concise Pexels search phrase",
    "pexels_description": "Plain-English description of the image to search for and choose"
  }
]
```

5. Run:

```bash
node scripts/publish-blog-post.mjs /tmp/dannflow-blog-posts.json
```

6. If publishing succeeds, do not paste the full article body. Return only:
   - Title
   - `edit_url`
   - `public_url`
   - Pexels keyword and image description
   - SEO quality score and any pre-publish warnings
   - Facebook caption and Reddit discussion prompt

If publishing fails because the project has not configured Supabase, report the missing variable and provide the draft-only package.

## Optional extra columns

The base DannFlow `blog_posts` table supports the core fields needed to publish a post. Some projects may add extra SEO/social columns such as:

- `image_alt_text`
- `image_caption`
- `pexels_credit_url`
- `primary_keyword`
- `search_intent`
- `internal_links`
- `facebook_caption`
- `reddit_discussion_prompt`
- `seo_quality_score`
- `pre_publish_warnings`

`scripts/publish-blog-post.mjs` only inserts extra columns when `BLOG_POST_EXTRA_COLUMNS` is set. Example:

```bash
BLOG_POST_EXTRA_COLUMNS=image_alt_text,image_caption,primary_keyword,search_intent node scripts/publish-blog-post.mjs /tmp/dannflow-blog-posts.json
```

## Final constraints

- Return exactly the requested `blog_count` number of posts. Default to one. Never exceed five.
- Keep repeated runs meaningfully different in topic, title frame, structure, examples, openings, and image keywords.
- Align every post with the current project from `business.json`; never use source-project-specific names or examples.
- Generate social drafts, but make Reddit community/discussion-first instead of promotional.
- Run a private SEO quality gate before publishing. Improve the draft if the estimated score is below 85.
